# The papers, and how to build and submit them

Two finished papers, both typeset and both compiling:

* **`joining-rotations.tex`** -- which rotations join two Moser lattices into a
  5-chromatic graph. 18 pages, 8 figures.
* **`v5-at-least-29.tex`** -- the order of a 5-chromatic unit-distance graph is
  at least 29, improving the published 28. 5 pages, no figures, independent of
  the other.

The `.md` files are the working drafts the `.tex` files were written from; the
`.tex` is the version of record in each case. `interface-bound.md` has been
folded into `joining-rotations.tex` as its Section 8 and is kept only as the
draft it was -- its numbers predate the nine-to-five correction and should not
be read on their own.

## Building

```bash
pdflatex joining-rotations.tex
pdflatex joining-rotations.tex      # twice, for \ref and the table of contents
pdflatex v5-at-least-29.tex
pdflatex v5-at-least-29.tex
```

No BibTeX run is needed: the bibliography is a manual `thebibliography`, which is
also what avoids arXiv's most common failure, a `.bbl` produced by a different
program than the one that compiled the document.

`tectonic` builds it too, and is what was used here:

```bash
tectonic -X compile joining-rotations.tex --outdir /tmp/texout
```

**Both compile clean** -- 18 pages with 8 figures, and 5 pages, no warnings
from the engine on either.

## Why this format

**Class: `amsart`, 11pt.** The AMS article class is the default for `math.CO`,
gives the theorem environments and the right math typography, and ships with TeX
Live, so arXiv has it. 11pt sits inside arXiv's required 10--14pt.

**Packages: none outside the TeX Live base.** `amsmath`, `amssymb`, `amsthm`,
`hyperref`, and the two encoding packages. arXiv provides only what TeX Live
provides; anything else would have to be bundled with the submission.

**Figures: eight PDFs in `figures/`.** arXiv does no on-the-fly conversion, so
figures must already be PDF, PNG or JPG for pdfLaTeX; these are vector PDFs, which
is the format it prefers and the one that stays sharp at any zoom. Each is
generated by a script in the same directory from the lattice itself --
`figures/README.md` has the table and the rebuild command.

**Two directories.** The `.tex` plus `figures/*.pdf`. `\graphicspath{{figures/}}`
is set, so the upload keeps that layout.

## Submitting

**arXiv, `math.CO`** is the right first destination: this community reads and
adjudicates there and in the Polymath16 comment threads. Two things to know.

* Upload the `.tex` and `figures/*.pdf`. Do **not** include `.aux`, `.log`,
  `.bbl` or the built `joining-rotations.pdf` -- arXiv strips or chokes on them,
  and a stray PDF with the document's own name will be mistaken for the output.
  The `.py`, `.png` and `.json` files in `figures/` do not belong in the upload
  either. Review the PDF arXiv generates before completing the submission; you
  are required to.
* **Endorsement.** arXiv changed its policy on 21 January 2026: an institutional
  email alone no longer grants automatic endorsement, and a first-time submitter
  without one needs a personal endorsement from an established arXiv author in the
  category. Worth arranging before the upload rather than after.

**Geombinatorics Quarterly** is where Parts, de Grey and the Polymath collective
write these results up, so it is the natural journal. Its house format is unusual
and is **not** what this `.tex` produces:

| | |
|---|---|
| page | 5.5in by 8.5in, landscape orientation |
| margins | 0.35in top/left/right, 0.5in bottom |
| font | Times New Roman 11pt, single spaced |
| title | capital bold 14pt; authors non-capital bold 11pt; address and email non-bold 11pt |
| page numbers | none -- the journal adds them |

Reformatting for them is a separate pass, and only worth doing once the arXiv
version is settled.
